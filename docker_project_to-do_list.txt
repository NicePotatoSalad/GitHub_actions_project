Tasks:
    1. Создайте Dockerfile: -- ✅
        - Напишите Dockerfile в корне вашего проекта. -- ✅
        - Он должен устанавливать Python и ваши зависимости (pytest, selenium). -- ✅
        - Он должен копировать ваш код тестов и устанавливать команду по умолчанию для запуска тестов. -- ✅

    2. Создайте docker-compose.yml и запустите локально: 
        - Опишите три сервиса: selenium-hub, selenium-node-chrome и ваш сервис для тестов (my-app-tests).
        - Убедитесь, что сервис my-app-tests использует ваш Dockerfile (build: .) 
        и зависит от selenium-hub.
        - Новый пункт: 
            Чтобы попробовать параллельное тестирование, вы можете добавить 
            больше selenium-node-chrome сервисов или настроить их в docker-compose так, 
            чтобы они запускались параллельно (например, используя опцию scale в 
            docker-compose up --scale node=3). Это покажет, как легко масштабировать тесты 
            с помощью Docker.
        - Запустите команду docker-compose up и убедитесь, что ваши тесты успешно проходят.

    3. Создайте .github/workflows/main.yml:
        - Настройте пайплайн GitHub Actions.
        - В секции services запустите Selenium Hub и Selenium Node. GitHub Actions 
            автоматически запустит их в одной сети.
        - Создайте шаг для сборки вашего образа из Dockerfile и запуска контейнера с тестами.
        - Убедитесь, что переменные окружения для подключения к Selenium Hub настроены правильно.

    4. Проверьте результаты:
        - Убедитесь, что ваш пайплайн успешно отрабатывает в GitHub Actions.
        - Это будет означать, что ваша тестовая среда, описанная в Dockerfile и docker-compose.yml, 
            работает как локально, так и в CI.
